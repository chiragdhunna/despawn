# Despawn: Crypto specification (v1)

Status: **normative**. This document makes `docs/ARCHITECTURE.md` section 5.2 byte-exact. Where the two differ, this document wins. The only intentional change from the architecture table: the release MAC also covers the wrap `nonce`.

Test vectors: [`crypto-vectors.json`](crypto-vectors.json), generated by an independent reference implementation. An implementation is correct only if it reproduces every vector exactly.

## 1. Conventions

- All integers are **big-endian**. `‖` is byte concatenation. `utf8(s)` is the UTF-8 encoding of the string, with no terminator and no length prefix.
- Labels are exact ASCII strings: `despawn/v1`, `despawn/v1/chan`, `despawn/v1/sas`, `despawn/v1/wrap`, `hello`, `release`.
- Only WebCrypto is used: AES-256-GCM, HKDF-SHA-256, HMAC-SHA-256, ECDH P-256, SHA-256, `getRandomValues`. No third-party crypto code.
- Text encoding of binary values: lowercase hex in tests and logs-free code, and **base64url without padding** (RFC 4648 section 5) for values in URLs and JSON.
- base64url decoding is **strict**: reject `=`, whitespace, any character outside `A-Z a-z 0-9 - _`, a length where `length mod 4 = 1`, and non-canonical encodings (the decoded bytes must re-encode to exactly the input string).

| Name | Bytes | Notes |
|---|---|---|
| `sessionId` | 16 | random |
| `linkSecret` | 16 | random, lives only in the URL fragment |
| `fileKey` (K) | 32 | random, AES-256 |
| `noncePrefix` | 4 | random, per session |
| GCM IV | 12 | |

## 3. Derivations

Let `sessionId`, `linkSecret`, `shopPub` (raw, 65 bytes), `ownerPub` (raw, 65 bytes).

### 3.1 Channel key

`chanKey = HKDF-SHA-256(IKM = linkSecret, salt = sessionId, info = utf8("despawn/v1/chan"), L = 32 bytes)`

Used only as an HMAC-SHA-256 key. Import as non-extractable with usages `sign` and `verify`.

### 3.2 Hello MAC (shop proves it holds the link secret)

`helloMac = HMAC-SHA-256(chanKey, utf8("hello") ‖ sessionId ‖ shopPub)`

### 3.3 SAS code

`digest = SHA-256(utf8("despawn/v1/sas") ‖ sessionId ‖ shopPub)`
`n = u32 big-endian of digest[0..4]`
`sas = (n mod 10000)` written as exactly 4 decimal digits, left-padded with zeros.

### 3.4 Wrap key

`shared = ECDH(ownerPrivate, shopPublic)` as 256 bits (the X coordinate), via `deriveBits`. Both sides derive the same value.
`W = HKDF-SHA-256(IKM = shared, salt = sessionId, info = utf8("despawn/v1/wrap") ‖ ownerPub ‖ shopPub, L = 32 bytes)`

### 3.5 Key wrap

`wrappedKey = AES-256-GCM-Encrypt(key = W, iv = nonce(12), plaintext = K, AAD = sessionId ‖ ownerPub ‖ shopPub)` which returns `ciphertext(32) ‖ tag(16)`.
`nonce` is 12 random bytes, sent alongside `wrappedKey`.

### 3.6 Release MAC

`releaseMac = HMAC-SHA-256(chanKey, utf8("release") ‖ sessionId ‖ ownerPub ‖ shopPub ‖ nonce ‖ wrappedKey)`

The shop must verify the release MAC **before** attempting to unwrap.

### 3.7 Chunk encryption

For chunk number `index` (starting at 0) and `isFinal` (boolean):

- `chunkNonce(12) = noncePrefix(4) ‖ u64(index)`
- `AAD = utf8("despawn/v1") ‖ sessionId(16) ‖ u32(index) ‖ u8(isFinal ? 1 : 0)`
- `sealed = AES-256-GCM-Encrypt(key = K, iv = chunkNonce, plaintext, AAD)` which returns `ciphertext ‖ tag(16)`.

Plaintext length per chunk is at most `CHUNK_SIZE`. Sealed length is plaintext length plus 16.

### 3.8 Stream rules

- Chunks are numbered consecutively from 0. Exactly one chunk, the last, has `isFinal = 1`.
- The encryptor **must** refuse to seal after the final chunk and must never reuse an index.
- The decryptor expects the next index in order. For each sealed chunk it first tries `isFinal = 0`, and if that fails authentication it tries `isFinal = 1`. If both fail, the result is `AUTH_FAILED`.
- After a final chunk is accepted, any further chunk is rejected with `AFTER_FINAL`.
- Calling `finish()` before a final chunk was accepted throws `TRUNCATED`.
- A reordered, duplicated, spliced or cross-session chunk fails authentication.
- The encryptor assigns each chunk its index synchronously at the moment seal() is called, before any asynchronous work, and copies all inputs at that moment. Concurrent or un-awaited calls therefore never share an index or nonce. Call order defines index order.
- If sealing fails after an index was assigned, the encryptor is permanently failed and every later seal() throws INVALID_INPUT. Argument validation errors (plaintext too large) do not assign an index and do not fail the encryptor.
- The decryptor processes open() calls strictly one at a time, in call order. Calls are queued, so concurrent calls can never accept a chunk twice or skip an index.
- Fail closed: once open() has thrown AUTH_FAILED or INVALID_INPUT, the decryptor is permanently failed. Every later open() throws AUTH_FAILED and finish() throws AUTH_FAILED. AFTER_FINAL after a completed stream does not mark the decryptor failed.

## 4. Validation and errors

Validate every input length before use. Public keys must be exactly 65 bytes starting with `0x04` and must be accepted by WebCrypto `importKey` (which rejects points not on the curve).

`CryptoError` has a `code`:

| Code | When |
|---|---|
| `INVALID_INPUT` | Wrong length, bad encoding, bad public key, chunk too large |
| `AUTH_FAILED` | Any MAC, GCM tag or unwrap failure |
| `TRUNCATED` | `finish()` called before the final chunk |
| `AFTER_FINAL` | Seal or open after the final chunk |

Error messages are **fixed strings per code**. They never contain keys, secrets, plaintext, lengths of secret data, or any input value.

Every public async function converts any unexpected platform exception into CryptoError with code INVALID_INPUT. Callers only ever see CryptoError.

```ts
export const SPEC_VERSION = 'despawn/v1';

export const LINK_SECRET_BYTES = 16;

export class CryptoError extends Error { readonly code: CryptoErrorCode; }

// bytes and encoding
export function utf8(s: string): Uint8Array;
export function concatBytes(...parts: Uint8Array[]): Uint8Array;
export function u32be(n: number): Uint8Array;           // 0 <= n <= 2^32-1, else INVALID_INPUT
export function u64be(n: number): Uint8Array;           // safe integer >= 0, else INVALID_INPUT
export function bytesToHex(b: Uint8Array): string;
export function hexToBytes(h: string): Uint8Array;
export function base64urlEncode(b: Uint8Array): string;
export function base64urlDecode(s: string): Uint8Array; // strict, see section 1
export function randomBytes(n: number): Uint8Array;     // loops internally if n > 65536
export function generateSessionId(): Uint8Array;
export function generateLinkSecret(): Uint8Array;
export function generateFileKeyBytes(): Uint8Array;
export function generateNoncePrefix(): Uint8Array;

// channel authentication
export function deriveChannelKey(linkSecret: Uint8Array, sessionId: Uint8Array): Promise<CryptoKey>;
export function computeHelloMac(channelKey: CryptoKey, sessionId: Uint8Array, shopPublicRaw: Uint8Array): Promise<Uint8Array>;
export function verifyHelloMac(channelKey: CryptoKey, sessionId: Uint8Array, shopPublicRaw: Uint8Array, mac: Uint8Array): Promise<boolean>;
export function computeSas(sessionId: Uint8Array, shopPublicRaw: Uint8Array): Promise<string>;

// key agreement and wrap
export interface EcdhKeyPair { privateKey: CryptoKey; publicKeyRaw: Uint8Array } // privateKey non-extractable
export function generateEcdhKeyPair(): Promise<EcdhKeyPair>;
export interface WrappedKey { nonce: Uint8Array; wrappedKey: Uint8Array }
export function wrapFileKey(p: {
  ownerPrivateKey: CryptoKey; ownerPublicRaw: Uint8Array; shopPublicRaw: Uint8Array;
  sessionId: Uint8Array; fileKey: Uint8Array; nonce?: Uint8Array; // nonce override is for test vectors only
}): Promise<WrappedKey>;
export function unwrapFileKey(p: {
  shopPrivateKey: CryptoKey; shopPublicRaw: Uint8Array; ownerPublicRaw: Uint8Array;
  sessionId: Uint8Array; nonce: Uint8Array; wrappedKey: Uint8Array;
}): Promise<CryptoKey>; // AES-GCM, usages ['decrypt'], extractable false
export interface ReleaseFields { sessionId: Uint8Array; ownerPublicRaw: Uint8Array; shopPublicRaw: Uint8Array; nonce: Uint8Array; wrappedKey: Uint8Array }
export function computeReleaseMac(channelKey: CryptoKey, f: ReleaseFields): Promise<Uint8Array>;
export function verifyReleaseMac(channelKey: CryptoKey, f: ReleaseFields, mac: Uint8Array): Promise<boolean>;

// chunks
export function importFileKey(raw: Uint8Array, usage: 'encrypt' | 'decrypt'): Promise<CryptoKey>; // non-extractable
export interface ChunkContext { sessionId: Uint8Array; noncePrefix: Uint8Array }
export interface ChunkEncryptor {
  seal(plaintext: Uint8Array, isFinal: boolean): Promise<Uint8Array>;
  readonly nextIndex: number;
  readonly finished: boolean;
}
export function createChunkEncryptor(key: CryptoKey, ctx: ChunkContext): ChunkEncryptor;
export interface ChunkDecryptor {
  open(sealed: Uint8Array): Promise<{ plaintext: Uint8Array; isFinal: boolean; index: number }>;
  finish(): void; // throws TRUNCATED if no final chunk was accepted
}
export function createChunkDecryptor(key: CryptoKey, ctx: ChunkContext): ChunkDecryptor;
```

`verify*` functions use WebCrypto `subtle.verify` (constant time) and return `false`, never throw, on mismatch. They still throw `INVALID_INPUT` for malformed lengths.

## 6. Required tests

Every item below must exist and pass. Load vectors from `docs/crypto-vectors.json`.

1. **Encoding:** base64url vectors encode and decode exactly. Reject `=`, `+`, `/`, whitespace, length mod 4 = 1, and the non-canonical string `AAECAwQFBgcICQoLDA0ODx`.
2. **Hello MAC:** `deriveChannelKey` plus `computeHelloMac` reproduces `helloMacHex`. `verifyHelloMac` accepts it and rejects a one-bit change, a wrong `sessionId`, a different `shopPub`, and a different `linkSecret`.
3. **SAS:** reproduces `sas` from the vectors. Changing `sessionId` or `shopPub` changes it (use at least 20 random inputs and expect at least one difference, plus the fixed vectors).
4. **Wrap:** with the vector nonce, `wrapFileKey` reproduces `wrappedKeyHex`. `unwrapFileKey` with the shop private key returns a key that opens the vector chunks. Unwrap fails with `AUTH_FAILED` for: wrong `sessionId`, modified `ownerPub`, modified `shopPub`, modified nonce, one flipped bit in `wrappedKey`.
5. **Release MAC:** reproduces `releaseMacHex`. Rejects a change to any one of its fields (each of the five, individually).
6. **Chunks, known answer:** the encryptor with the vector key and context reproduces both `sealedHex` values, including nonce and AAD behaviour for index 0 (not final) and index 1 (final).
7. **Chunks, tamper:** one flipped bit in ciphertext, in the tag, wrong key, wrong `sessionId`, wrong `noncePrefix` each give `AUTH_FAILED`. Swapping two chunks gives `AUTH_FAILED`. Dropping the final chunk then calling `finish()` gives `TRUNCATED`. Feeding a chunk after the final gives `AFTER_FINAL`. Replaying chunk 0 in position 1 gives `AUTH_FAILED`.
8. **Chunks, limits:** a plaintext of `CHUNK_SIZE` seals and opens. `CHUNK_SIZE + 1` gives `INVALID_INPUT`. The encryptor refuses to seal after the final chunk. A multi-chunk round trip (for example 5 chunks of random sizes, last one empty) works.
9. **Key agreement:** `generateEcdhKeyPair` private keys are non-extractable (`extractable === false`). Both sides derive the same wrap key (shown through a successful round trip). Invalid public keys (wrong length, prefix `0x02`, a point not on the curve) give `INVALID_INPUT`.
10. **Key objects:** the key returned by `unwrapFileKey` has `extractable === false` and usages exactly `['decrypt']`. `importFileKey` keys are non-extractable.
11. **Errors:** error messages are constant per code and contain none of the input bytes (assert that no error message contains a hex or base64url rendering of the key or plaintext used in the test).
12. **Full flow:** an end-to-end test that plays the owner and the shop: generate ids, derive the channel key, shop hello and MAC verify, SAS equal on both sides, owner wrap and release MAC, shop verify then unwrap, owner seals three chunks, shop opens them and the final flag matches.
13. **Misuse and concurrency:**
    - Firing 50 un-awaited `seal()` calls with `Promise.all` assigns distinct indices 0..49; a fresh decryptor opens all in order and finish() succeeds; nextIndex is 50 and finished is true.
    - Two un-awaited `seal()` calls receive indices 0 and 1 in order.
    - Concurrent duplicate `open()` calls on the same chunk reject one and fulfill one.
    - Concurrent in-order `open()` calls (chunks 0, 1, 2) fulfill with indices 0, 1, 2 in order.
    - Fail closed: after `open()` throws `AUTH_FAILED`, subsequent `open()` and `finish()` calls throw `AUTH_FAILED`.
    - Failing `seal()` (e.g. key without encrypt usage) permanently poisons the encryptor; argument errors (oversized plaintext) do not poison a healthy encryptor.
    - Raw platform errors never escape: passing wrong-type keys to all public async functions rejects with `CryptoError`.
    - `AFTER_FINAL` on a completed stream throws `AFTER_FINAL`, not `AUTH_FAILED`.

## 7. Not in this package

The bundle format, networking, the session state machine, rendering, UI and storage are separate packages and tasks. This package is pure functions and small stateful encryptor and decryptor objects with no I/O.
